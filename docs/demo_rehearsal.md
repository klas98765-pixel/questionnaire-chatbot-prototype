## 1. 프로젝트 소개 — 20~30초

“이 프로토타입은 고정된 가상 11문항을 대화형 화면에서 진행합니다.
버튼과 규칙 기반 한국어 명령으로 문항을 이동하고, 응답을 확인·수정할 수 있습니다.
오류가 나도 기존 응답을 유지하도록 설계했습니다.
실제 임상척도가 아니며 진단이나 임상 점수를 제공하지 않습니다.”

## 2. 환경과 실행

실제로 확인한 환경: 로컬 macOS, Python 3.11.18, 기존 `.venv`, Streamlit.
아래 명령은 프로젝트 루트에서 실행합니다. 이번 리허설에서 패키지를 새로 설치하지 않았습니다.

```sh
.venv/bin/python -m streamlit run app.py --server.headless true --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
```

브라우저에서 `http://127.0.0.1:8501`을 엽니다.
터미널의 종료는 Ctrl+C입니다. 검증 작업 종료 후 서버는 종료했습니다.
발표 때는 위 명령으로 다시 시작해야 합니다.

자동 테스트:

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_*.py' -v
```

시연 전 준비:

- Track A 저장소와 `feature/chatbot-ui` 브랜치인지 확인합니다.
- 터미널에서 서버 기동 성공을 확인한 뒤 브라우저를 엽니다.
- 넓은 창을 사용하고 입력창·선택지·이동 버튼 위치를 미리 확인합니다.
- 자연어 명령은 아래에서 검증한 문구를 그대로 사용합니다.
- 동작 결과와 현재 문항을 확인한 뒤 다음 클릭·입력을 진행합니다.
- 새로고침은 세션을 초기화합니다. 두 시나리오 사이에서만 의도적으로 사용합니다.
- 응답은 선택지 버튼으로 입력합니다. 자연어 입력창은 진행 명령용입니다.

## 3. 정상 응답 시나리오 — 약 1분

1. 최초 화면의 환영 메시지, 0%, 응답 0·건너뜀 0·미응답 11을 보여줍니다.
2. ‘설문 시작하기’를 누릅니다. 1번 질문과 5개 선택지가 표시됩니다.
3. ‘가끔’을 누릅니다. 저장된 응답이 표시되고 위치는 1번으로 유지됩니다.
4. ‘다음’을 눌러 2번으로 이동합니다.
5. 2~11번도 ‘가끔’ → ‘다음’을 반복합니다.
6. 11번 응답 저장 직후에는 11번에 머무르고, ‘다음’을 누르면 최종 검토가 표시됩니다.
7. 응답 11·건너뜀 0·미응답 0, 진행률 100%와 요약 11행을 보여줍니다.
8. ‘설문 완료 확정’을 누릅니다. 완료 안내와 결과표가 표시됩니다.
9. “방금 답변 수정할게”를 입력합니다. ‘응답 수정하기’ 버튼을 사용하라는 안내가 나오고 완료 상태가 유지됩니다.

설명: “응답 저장과 이동은 별개이고, 검토와 완료 확정도 별개입니다.”

## 4. 자연어 시나리오 — 약 2분 30초

브라우저를 새로고침해 시작 화면으로 돌아갑니다.

| 순서 | 조작·입력 | 기대 화면 |
|---|---|---|
| 1 | 설문 시작하기 → 1번 ‘가끔’ | 1번에 저장, 자동 이동 없음 |
| 2 | 다음 질문으로 넘어가 줘 | 2번 표시 |
| 3 | 3번 질문으로 이동해 줘 | 3번 표시; 2번은 미응답 유지 |
| 4 | 이 질문은 건너뛸게 | 4번 표시; 응답 1·건너뜀 1·미응답 9 |
| 5 | 이전 질문 보여줘 | 3번으로 복귀, 건너뛴 문항 안내 |
| 6 | ‘자주’ 선택 | 3번 응답 저장, 건너뜀 해제 |
| 7 | 지금 몇 번째 질문이야? | 현재 3/11, 응답 2·건너뜀 0·미응답 9, 18% |
| 8 | 1번 질문에 뭐라고 답했어? | ‘가끔’ 안내, 위치·응답 불변 |
| 9 | 2번 | 모호한 명령 안내, 3번 위치와 집계 유지 |
| 10 | 설문을 끝내고 싶어 | 최종 검토; 미응답 9개, 완료 확정 비활성화 |
| 11 | 설문 계속 작성하기 | 첫 미응답인 2번으로 이동 |
| 12 | 2번 ‘건너뛰기’ | 3번으로 이동 |
| 13 | 3번 ‘다음’ | 이미 저장된 ‘자주’를 유지하고 4번으로 이동 |
| 14 | 4~11번 ‘건너뛰기’ 반복 | 마지막 처리 후 최종 검토 |
| 15 | 요약 확인 | 응답 2·건너뜀 9·미응답 0, 100% |
| 16 | 설문 완료 확정 | 완료 화면 |
| 17 | 3번 질문의 답변 수정할래 | 완료 상태 유지, 명시적 수정 모드 안내 |

선택 설명: “마지막에 건너뛰더라도 응답 처리 상태가 기록되므로 완료할 수 있습니다.
완료 요청 문장만으로는 완료 확정이 실행되지 않습니다.”

## 5. 오류 처리 시연 — 약 20~30초

필수 시연에서는 위의 ‘2번’과 미응답 완료 차단을 사용합니다.
추가 질문이 있으면 진행 중 새 세션에서 다음 사례를 보여줄 수 있습니다.

- 1번에서 미응답으로 ‘다음’: 응답 또는 건너뛰기 안내, 이동 없음.
- 1번에서 ‘이전’: 첫 문항 안내, 앱 중단 없음.
- “다음 질문으로 넘어가지 마”: 명령을 실행하지 않음.
- “12번 질문으로 이동해 줘”: 유효하지 않은 번호 안내, 위치 유지.
- “이전 질문으로 가서 답을 바꿀게”: 한 번에 하나씩 명확하게 입력하도록 안내.

위 추가 사례는 기존 자동 테스트에 포함됩니다. 이번 5-B 브라우저 리허설에서는
지정된 ‘2번’, 미응답 완료 차단, 완료 후 수정 차단을 직접 확인했습니다.
추가 사례 전체를 이번 브라우저에서 다시 실행했다고 설명하지 않습니다.

## 6. 발표 핵심 기술 — 약 20~30초

- 고정 콘텐츠: `questionnaire.py`의 가상 11문항과 5개 응답 코드.
- 명령 흐름: `parse()` → `ParseResult` → Router 검증·상대 참조 해소 → Action → `execute()` → SurveyEngine.
- 버튼도 같은 실행기를 사용하며, 자연어 GOTO는 Parser가 추출한 번호를 사용합니다.
- 조회는 상태를 변경하지 않고, EDIT는 새 선택을 안내합니다.
- SurveyEngine은 후보 상태를 검증한 후 반영합니다. 실패한 명령은 기존 응답을 보존합니다.
- Streamlit session_state가 엔진 인스턴스를 유지합니다. 대화 기록은 표시용입니다.
- 완료 확정은 버튼으로만 수행합니다.

계획 시간 합계: 약 4분 10초~4분 30초.
이는 발표용 권장 배분이며, 발표자의 설명을 포함한 실제 사람의 3~5분 진행 시간은 측정하지 않았습니다.
정상 시나리오를 짧게 보여주고 자연어 시나리오에 설명을 집중합니다.

## 9. 제한 사항과 미검증 항목

- 규칙에 등록된 한국어 명령 표현만 지원합니다. 임의의 모든 자연어를 이해하지 않습니다.
- 설문 응답은 선택지 버튼으로 저장합니다. 자유서술 응답을 선택지로 추론하지 않습니다.
- 문항은 고정 가상 데이터입니다. LLM 질문 생성·환자별 적응형 임상 문진은 없습니다.
- 실제 K-IADL, 진단, 임상 판단, 임상 점수 산출을 구현하지 않았습니다.
- 영구 저장·DB·새로고침 이후 복구는 없습니다.
- 실제 환자나 개인정보를 사용하지 않았습니다.
- 다중 사용자 부하, 다른 OS·브라우저 전체, 모바일·스크린리더 접근성은 이번 리허설에서 검증하지 않았습니다.
- 사람 발표 기준 3~5분 소요시간과 실제 연구실 프로젝터 가독성은 아직 측정하지 않았습니다.
- 실제 사용자 대상 사용성 연구를 수행한 결과가 아니라 개발 리허설 관찰입니다.

## 10. 발표 중 문제가 생기면

명령이 인식되지 않으면 문구를 위 표대로 입력하거나 해당 버튼으로 같은 기능을 보여줍니다.
미응답 완료 차단은 오류가 아니라 의도된 보호 규칙입니다.
기능 오류나 상태 불일치가 보이면 즉시 시연을 멈추고 입력·문항·저장값을 기록합니다.
새로고침하면 응답이 사라지므로 진행 중 무심코 새로고침하지 않습니다.
이번 리허설에서는 기능 오류가 발견되지 않았고 코드 수정은 수행하지 않았습니다.
