# Questionnaire Chatbot Prototype

## 프로젝트 개요

Track A의 대화형 설문 챗봇 MVP입니다. 최근 7일의 일상생활 활동 경험을 묻는 **고정 가상 11문항**에 답하고, 버튼 또는 규칙 기반 한국어 명령으로 설문을 진행합니다.

실제 K-IADL 원문이나 환자정보를 사용하지 않습니다. 임상척도·진단 도구가 아니며, 임상 연구용으로 검증된 시스템이 아닙니다. 별도 Track B 연구와 구분하여 실행 가능한 프로토타입 개발에 집중합니다.

현재 구현은 **`feature/chatbot-ui` 브랜치**에 있습니다. 아래 설치 과정에서도 이 브랜치를 선택합니다.

## 주요 기능

- 설문 시작 및 11문항 순차 진행
- 5개 선택지 응답 즉시 저장, 저장 후 현재 문항 유지
- 이전·다음 이동 및 1~11번 특정 문항 이동
- 건너뛰기, 기존 응답 확인·수정, 건너뛴 문항 재응답
- 현재 위치, 응답·건너뜀·미응답 개수와 진행률 표시
- 규칙 기반 자연어 이동·수정 요청 및 진행·이전 응답 조회
- 전체 응답 최종 검토와 별도의 완료 확정
- 완료 후 명시적인 수정 모드 재진입
- 잘못된 명령의 안내와 설문 상태 보존

**응답 저장과 다음 이동은 별개입니다. 최종 검토와 완료 확정도 별개입니다.**

## 기술 스택

| 구성 | 사용 기술 |
|---|---|
| 실행 언어 | Python 3.11 기준 (`pyproject.toml` 요구사항: Python 3.11 이상) |
| 웹 UI | Streamlit (`streamlit>=1.40,<2`) |
| 명령 해석 | Python 정규식 기반 한국어 전체 발화 패턴 |
| 상태 | Python 데이터 모델·엔진, Streamlit `session_state` |
| 테스트 | 표준 `unittest`, Streamlit `AppTest` |
| 패키징 | setuptools, `src/` 패키지 구조 |

외부 API 호출, API 키, 외부 데이터 다운로드는 필요하지 않습니다. 설치 시 Python 패키지 다운로드를 위한 네트워크 연결은 필요합니다.

## 시스템 동작 구조

```text
사용자 자연어 입력
  → RuleBasedIntentParser.parse() → ParseResult
  → Intent Router (의도·진행 단계 검증, 대상 문항 해석)
  → Action Executor (execute) → SurveyEngine → 화면 갱신

버튼 입력 → Action → 같은 Action Executor → SurveyEngine → 화면 갱신
```

| 구성요소 | 역할 |
|---|---|
| Streamlit UI (`app.py`) | 버튼·대화 입력 수집, 대화 기록·현재 문항·요약 표시 |
| RuleBasedIntentParser | 등록된 문장 패턴을 구조화된 Intent와 문항 참조로 변환 |
| Intent Router | 상대 참조 해소, 조회 처리, 명령을 Action으로 변환 |
| Action Executor (`actions.py`) | 공통 Action을 기존 엔진 메서드에 연결 |
| SurveyEngine | 설문 상태의 단일 기준, 이동·응답·검토·완료 규칙 검증 |
| Questionnaire Data | 고정 문항 번호·문구와 응답 코드·한국어 표시 문구 |
| Session State | 같은 브라우저 세션의 앱 재실행 동안 엔진과 UI 기록 유지 |

조회는 엔진을 읽고 결과만 표시하며 상태 변경용 Action을 실행하지 않습니다. Parser도 설문 상태를 수정하지 않습니다. 엔진은 복사한 후보 상태를 검증한 뒤 반영합니다. 대화 기록은 표시용이며 실제 응답을 복원하거나 판단하는 기준으로 사용하지 않습니다.

## 실제 사용 방법

1. **설문 시작하기**를 누릅니다. 시작 전 자연어 입력은 비활성화되어 있습니다.
2. 현재 문항의 응답 버튼을 누릅니다. 저장값과 강조된 선택지로 응답을 확인합니다. 자동 이동하지 않습니다.
3. **다음**으로 이동합니다. 미응답이면 이동이 차단되므로 응답하거나 **건너뛰기**를 선택합니다.
4. **이전**, 문항 선택 상자와 **선택 문항으로 이동**, 또는 자연어로 문항을 이동합니다. 이전·번호 지정 이동은 현재 문항이 미응답이어도 가능합니다.
5. 응답을 수정하려면 해당 문항에서 다른 선택지를 누릅니다. 다른 문항의 응답은 유지됩니다.
6. **최종 검토**를 누르거나 마지막 문항 처리 후 검토로 이동합니다. 11번에 응답한 경우 **다음**을 눌러야 하며, 11번을 건너뛰면 검토로 바로 이동합니다.
7. 검토표의 미응답이 있으면 **설문 계속 작성하기**로 돌아갑니다. 첫 미응답 문항이 표시됩니다.
8. 미응답이 0개이면 **설문 완료 확정**을 누릅니다. 건너뛴 문항은 완료 가능한 상태로 인정합니다.
9. 완료 후에는 조회만 가능하며 변경하려면 **응답 수정하기**를 눌러야 합니다. 기존 응답을 유지한 채 1번으로 돌아가고, 수정 후 다시 검토·완료합니다.

### 응답과 건너뜀

| 저장 코드 | 표시 문구 |
|---|---|
| `NEVER` | 전혀 하지 않음 |
| `RARELY` | 드물게 |
| `SOMETIMES` | 가끔 |
| `OFTEN` | 자주 |
| `UNSURE_OR_NA` | 모르겠음·해당 없음 |

코드는 저장용이며 점수·가중치가 없습니다. ‘모르겠음·해당 없음’도 저장된 응답입니다. **건너뜀**은 응답을 저장하지 않은 별도 상태입니다. 이미 응답한 문항의 건너뛰기는 거부하며, 건너뛴 문항에 답하면 건너뜀을 해제합니다.

진행률은 `(응답 수 + 건너뜀 수) / 11`입니다. 정답률이나 임상 점수가 아닙니다.

## 지원하는 자연어 명령 예시

다음 문장은 현재 Parser가 인식하는 예시입니다. **응답 자체는 선택지 버튼으로 저장합니다.**

| 입력 | 실제 동작 |
|---|---|
| 다음 질문으로 넘어가 줘 | 응답·건너뜀 상태일 때 다음 이동 |
| 이전 질문 보여줘 | 바로 이전 문항 이동; 1번이면 안내 |
| 3번 질문으로 이동해 줘 | 선택 상자 값과 무관하게 3번 이동 |
| 이 질문은 건너뛸게 | 현재 미응답 문항을 건너뛰고 다음 이동 |
| 지금 몇 번째 질문이야? | 위치·응답·건너뜀·미응답·진행률 조회 |
| 1번 질문에 뭐라고 답했어? | 해당 문항 응답을 한국어로 조회 |
| 현재 질문의 답변 보여줘 | 현재 문항 응답 조회 |
| 이전 질문의 답변 보여줘 | 바로 이전 번호 문항 응답 조회 |
| 내가 앞에서 뭐라고 답했지? | 마지막으로 응답을 저장한 문항 조회 |
| 방금 답변 수정할게 | 마지막 저장 문항으로 이동하거나 수정 안내; 응답은 자동 변경하지 않음 |
| 3번 질문의 답변 수정할래 | 저장 응답이 있는 3번으로 이동하고 새 선택 안내 |
| 최종 검토 화면 보여줘 | 검토 화면으로 이동 |
| 설문을 끝내고 싶어 | 검토로 안내; 완료는 버튼으로만 확정 |

마지막 응답 문항을 확인할 수 없으면 번호를 명시하도록 안내합니다. 검토 중에는 변경 명령 대신 **설문 계속 작성하기**를, 완료 후에는 **응답 수정하기**를 사용합니다.

모호하거나 잘못된 입력은 실행하지 않습니다.

- `2번`: 작업이 불분명하므로 명확한 명령 요청
- `다음 질문으로 넘어가지 마`: 부정 명령 거부
- `다음 주에 할게`: 지원하지 않는 입력 안내
- `이전 질문으로 가서 답을 바꿀게`: 복합 명령을 한 번에 실행하지 않음
- `12번 질문으로 이동해 줘`: 범위 밖 번호 거부

## 현재 구현 범위 및 제한 사항

현재는 고정 설문을 진행하고 응답·상태를 세션 메모리에서 관리하는 시연용 MVP입니다.

- 고정된 가상 11문항만 사용하며 실제 K-IADL 원문은 사용하지 않습니다.
- 실제 임상척도나 임상 연구용으로 검증된 시스템이 아닙니다.
- LLM 질문 생성, 환자별 적응형 질문 생성은 구현하지 않았습니다.
- 실제 환자정보 처리, 임상 점수 산출, 진단·임상 판단 기능이 없습니다.
- DB·영구 저장·세션 종료 후 복구를 지원하지 않습니다. 브라우저 새로고침 시에도 상태가 초기화됩니다.
- 등록된 규칙 범위의 명령만 인식하며, 자유로운 모든 자연어를 이해하지 않습니다.
- 자유서술 응답 저장·선택지 추론을 지원하지 않습니다.
- 실제 원본 공공데이터를 포함하지 않으며 외부 데이터 없이 실행합니다.

## 향후 확장 가능성

다음 항목은 **현재 미구현인 후속 연구 방향**입니다.

- LLM 기반 자연어 이해 및 기존 규칙 방식과의 비교
- 적절한 데이터 이용·검증 절차를 전제로 한 임상 데이터 연동
- 환자별 질문 생성·재계획과 설문 상태·임상 정보 결합
- 로그·응답 저장 및 세션 복구
- 실제 사용자 대상 사용성 평가

이 방향들은 별도 요구사항과 검증이 필요하며 현재 MVP의 임상적 유효성을 의미하지 않습니다.
